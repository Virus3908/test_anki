# Грамматика N5–N1

## Источник и лицензия

526 правил (81/98/101/123/123), 1526 японских примеров OpenJLPT 0.3.0,
commit `0d1d3410bec90bd4098a7c72de820543cb4f707c`.
`tools/grammar/upstream` сохраняет исходные JSON и CITATION; snapshot.json
фиксирует SHA-256. В `Data/Grammar` находятся CC BY-SA 4.0 LICENSE, исходный
NOTICE и Grammar-NOTICE. Производные учебные задания распространяются под
CC BY-SA 4.0; лицензия Swift-кода не меняется. Японские исходные примеры,
английские поля, ID и порядок сохраняются. Новые Tatoeba-примеры не добавлены.

## Ресурсы и воспроизводимость

`python3 tools/grammar/generate.py` — разрешённая локальная генерация, не тест.
Генератор использует только vendored snapshot и `author_exercises.py`, без сети.
Ресурсы `grammar-n5.json` … `grammar-n1.json` имеют schemaVersion 1 и metadata;
уникальные имена учитывают flattening ресурсов Bundle в Xcode. Manifest сообщает
объёмы и распределение типов. `GrammarDataLoader` — actor с кешем декодирования,
проверкой основных обязательных полей, ID, версии, атрибуции и категорий.
Тяжёлое декодирование не выполняется в body/MainActor. Есть выбор уровня,
ID, категории, связанных правил и отменяемый поиск вне MainActor.

Модель `GrammarRule` отделяет исходные поля, необязательную адаптацию,
примеры, задания и связи от прогресса. `GrammarExercise` хранит стабильные
exercise/option ID, acceptedOptionIDs, русский вопрос/обратную связь,
английскую учебную подсказку/объяснение для перевода и provenance.
Provenance: commit, sourceRuleID, exampleIndex, method, status.
Статусы draft / automaticallyChecked / linguisticallyReviewed различаются.
Reviewer необязателен; для заявленного лингвистического ревью CI требует
реального reviewer. Само наличие строки не доказывает такого ревью.

Повреждённые упражнения одного правила декодируются как недоступная практика:
остальные уроки не блокируются, показана явная ошибка, оценка не сохраняется.
Ошибки базовых ресурсов/обязательного содержания по-прежнему throwing;
нет успешной пустой загрузки вместо отсутствующего уровня.

## Перевод на телефоне

По уточнённому требованию пользователя в Bundle хранится английский оригинал,
а русский перевод выполняется телефоном, аналогично кандзи. Используются прежние
TranslationViewModel, SystemRussianMeaningTranslator, системная очередь и
TranslationRepository. Ключ `grammar-content:<id>:ru` добавлен в существующий
TranslationStore; новая база/хранилище не создаются, старые записи совместимы.

Переводятся значение, формула, notes, английские переводы всех примеров,
подсказки и исходные пояснения заданий. Японские фрагменты защищены маркерами;
при потере/дублировании маркера показывается оригинал. Есть переключение
оригинала, повторный перевод и прежняя настройка языка колоды. Отмена задач и
fingerprint исходных текстов используют прежний переводческий pipeline.
Просмотр правила не меняет SRS. После появления кеша он используется и в списке.

Все исходники и упражнения офлайн. Первый системный перевод может потребовать
установки языковых моделей средствами iOS. Без модели и сохранённого перевода
показывается английский оригинал; это не фиктивный русский перевод. После
кеширования русский текст доступен офлайн. Машинный перевод не является
ручной лингвистической проверкой, особенно для нюансов N2/N1.

## Сценарий урока

1. Новое правило: объяснение, формула, особенности и реальные примеры с фуриганой.
2. «Перейти к упражнениям»: три заранее подготовленных задания.
3. Выбор ответа: правильный и выбранный ошибочный варианты выделяются иконками,
   текстом и семантическими цветами; появляется разбор. Ответ нельзя изменить
   повторным нажатием. Кнопка продолжения доступна после ответа.
4. «Урок завершён»: счёт, ошибки, правильные варианты и пояснения. Результат
   автоматически сохраняется одним ответом FSRS; после сохранения показана dueDate.
5. «Следующее правило» перестраивает ту же очередь и продолжает обучение.
   Завершение дня использует прежний лист дополнительных карточек.

Повторение начинает задания сразу; «Посмотреть правило» доступно всегда.
При ошибке сохранения результат остаётся, можно повторить сохранение.
Нормальный режим никогда не подменяет отсутствующие задания RecallPrompt.
Открытая самопроверка сохранена как явно включаемый дополнительный domain-режим,
не основной интерфейс. Выход не создаёт ответы за непройденный урок.

`GrammarPracticeViewModel` управляет вопросами, выбором, результатами и закрытием;
UI не оценивает ключи/FSRS. `GrammarExerciseSelection` детерминированно выбирает
три задания и перемешивает варианты по ruleID/числу FSRS-прохождений. Новые
упражнения не сбрасывают правило. При повторениях меняются порядок/набор, когда
пул больше трёх. Непроверенные японские предложения в runtime не генерируются.

## Типы и качество заданий

Все пять типов поддерживают выбор готового ответа: chooseConstruction,
fillBlank, identifyConstruction, chooseCorrectSentence, transformSentence.
У каждого правила минимум три задания/два типа, в корпусе 2440 заданий.

Выбор конструкции сопоставляет значение/формулу исходника с паттерном;
определение — реальный пример и его перевод с правилом. Выбор употребления
просит найти предложение с нужной конструкцией: остальные варианты — настоящие
грамматически корректные предложения других правил, а не вымышленные ошибки.
Пропуск буквально восстанавливает исходный пример. Преобразование たい — явно
составленный выбор желания вместо факта/отрицания, правильный ответ из источника.

Ключ ответа — множество ID, не позиция кнопки; неизвестный ID не принимается.
Несколько допустимых вариантов модель поддерживает, если это явно задано.
Полный ручной лингвистический аудит корпуса не проводился. Автоматическая
проверка устанавливает связь с исходником, не все семантические различия.
Подробный объём/ограничения: [grammar-quality.md](grammar-quality.md).

## FSRS и жизненный цикл

`GrammarLessonRating`: 0/3 или 1/3 → Again; 2/3 → Hard; 3/3 → Good.
Для более длинного прохода Good только при 100%, Hard от 2/3, иначе Again;
проход короче трёх или некорректный результат не оценивается. Easy автоматически
никогда не назначается. Тесты политики детерминированы.

PracticeMode.grammar, колоды grammar:n5 … n1 и ключи grammar:<upstreamID>.
StudyCardCatalog и StudyAppViewModel+Grammar запускают прежнюю сессию. Используются
тот же TrainingSessionEngine, StudyProgressStore, неизменённый StudyScheduler
FSRS-6 и ReviewRepository/review-memory.json. Формат истории, старые keys и
параметры FSRS не меняются. Одна конструкция — одна запись, не запись на вопрос.

Сохранённый результат удерживается `isGrammarResultPending` в существующем
TrainingSessionViewModel. Повторная отправка заблокирована; timer не перестраивает
экран результата. Продолжение перестраивает очередь без второго FSRS-ответа.
Undo удаляет последнюю запись лога и восстанавливает прежний SRS record;
учебные ответы сбрасываются и правило проходится заново. Это явная семантика,
а не восстановление ошибочно сохранённых трёх отдельных ответов. Сохранённый
SRS переживает перезапуск; незаконченное упражнение не персистируется.

Learning/relearning/review, лимиты, день, дополнительные карточки, reset,
расписание и свободный выбор используют прежнюю очередь. Остаток сегодня —
todayIDs, включая ожидающие learning. Уровни открыты без блокировки N4–N1.

## Интерфейс и проверка

Главная → уровень → правило/последовательное обучение/повторение.
previewHeader, BottomActionBar, GlassIconButton, appSurfaceCard,
CenteredLoadingIndicator и AppPalette общие с прежними экранами. Действия
закреплены внизу; scroll содержит длинный материал. Нижний переключатель имеет
горизонтальную прокрутку полных подписей и масштабируется с Dynamic Type.

Фуригана использует прежние FuriganaParser/FuriganaText; реконструкция должна
точно совпасть с исходным японским текстом. Неизвестное чтение не выдумывается.
Поиск и sourceMention-связи сохранены; sourceMention не означает эквивалентность.
Статистика/подсветка берут реальные SRS состояния/CardMastery, не процент знания.

Все тесты/автоматические проверки — только GitHub Actions. Два grammar jobs
сохранены, readiness проверяет исходники для перевода на устройстве согласно
уточнению пользователя и полноценность заданий. Проверки >=3 заданий/двух типов,
четырёх уникальных вариантов и всех пяти типов не отключены. Hosted tests
проверяют модели, ошибочные данные, политику оценки, shared persistence/Undo,
защиту переводов и совместимость. UI tests сохраняют снимки этапов урока,
правильного/ошибочного ответа и результата; CI выбирает компактный установленный
iPhone. Отдельный сценарий увеличивает Dynamic Type только в Debug UI-режиме.
Снимки экспортируются в artifact grammar-ui-screenshots для визуального ревью.
Локально разрешены генерация/статический анализ/device build, не тесты/Simulator.
